# Между парами

Небольшой одиночный 2D симулятор студенческой жизни с элементами RPG и стратегии. Игрок проходит первый курс университета: живёт в общаге, развивает характеристики, учится, работает и строит отношения.

История охватывает два семестра. Зимняя сессия даёт промежуточный результат, летняя сессия и эпилог завершают первый курс. Основной выбор — как распределить ограниченные время, деньги и энергию между собственными планами и обязательствами перед другими людьми.

## Состояние проекта

Разработка начата: Unity-проект находится в `Unity/`, используется редактор **6000.3.24f1**, шаблон Universal 2D и Input System. Первый прототип — одна комната общаги и три периода игрового дня с учёбой, простой работой и отдыхом. Графика временная. Полный первый курс, сюжетные квесты, питание, платежи и сохранения ещё не реализованы.

## Быстрый вход в работу

1. Прочитать [текущее состояние](DEVELOPMENT_STATE.md): что уже работает, чем проверено и какой шаг следующий.
2. Открыть [план](Development_Plan.md) на нужном этапе. Полный геймдизайн читать по необходимости.
3. Открыть папку `Unity/` в Unity 6000.3.24f1, затем сцену `Assets/MezhduParami/Scenes/PrototypeDorm.unity` и нажать Play.

Управление: WASD или стрелки — движение, E — взаимодействие, Enter — подтверждение, Esc — отмена или пауза. Выбор героя доступен при старте. В прототипе варианты отличаются временным цветовым обозначением; полноценные спрайты готовятся отдельно.

Три значимых действия завершают тестовый день. Ходьба и разговор с Сашей не расходуют период. Оплачиваемая смена доступна один раз за день. Это прототип управления и цикла действий, а не финал всей игры.

## Команда

- Технический разработчик — код, управление, игровые системы, интерфейс, сохранения и сборка.
- Разработчик контента — графика, окружение, звук, сценарии квестов, диалоги и тестовые прохождения.
- Тимлид-аналитик — приоритеты, исследование аудитории и фиксация решений.

Геймдизайн и проверка результата — совместная работа команды. Бюджет двух разработчиков: восемь недель по десять часов на человека, всего 160 человеко-часов.

## Работа с репозиторием

Основная ветка — `main`. Изменения делаем в отдельных ветках и объединяем после проверки. Не редактируем одновременно один файл сцены или префаба: перед работой договариваемся о владельце.

После создания Unity-проекта сохраняем в Git исходники, папки `Assets`, `Packages`, `ProjectSettings` и файлы `.meta`. Служебные каталоги `Library`, `Temp`, локальные настройки и сборки исключены через `.gitignore`.

## Проверка и сборка

Проверки находятся в `Unity/Assets/MezhduParami/Tests/`: EditMode проверяет расчёты дня, PlayMode — движение, препятствия, взаимодействие и отмену.

Windows-сборку создаёт метод `MezhduParami.Editor.PrototypeSceneBuilder.BuildWindows`; результат находится в `Builds/Windows/MezhduParami.exe`. Каталог сборок исключён из Git. Для сборки через Unity CLI при закрытом редакторе:

```powershell
unity run Unity -- -executeMethod MezhduParami.Editor.PrototypeSceneBuilder.BuildWindows
```

Для работы через агента используется Pipeline. Если редактор уже открыт, обращаться к нему через Unity CLI с явным `--project-path`, не запускать второй редактор для той же папки.
